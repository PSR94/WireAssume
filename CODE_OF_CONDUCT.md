# Code of Conduct

## Our standards

WireAssume contributors and maintainers are expected to create a respectful, technically rigorous, and welcoming collaboration environment.

Examples of constructive behavior include:

- giving specific, actionable feedback about code, tests, evidence, and design tradeoffs;
- assuming good intent while still challenging unsupported technical claims;
- documenting limitations and uncertainty instead of overstating results;
- respecting privacy when discussing captured traffic, logs, security findings, or user data;
- focusing disagreements on ideas and observable behavior rather than people.

Unacceptable behavior includes harassment, discriminatory or demeaning language, threats, publishing another person's private information without permission, deliberately exposing secrets or private traffic, and sustained disruption of project discussions.

## Scope

This code applies in repository issues, pull requests, reviews, discussions, project chat spaces, and other public spaces where someone is representing WireAssume.

## Enforcement

Report conduct concerns privately to the repository maintainer through an appropriate private GitHub contact channel. Do not include unrelated credentials, private traffic captures, or sensitive vulnerability details in a public conduct report.

Maintainers may edit or remove comments, commits, issues, reviews, or other contributions that violate these standards and may temporarily or permanently restrict participation when necessary to protect the community.

## Technical integrity

Because WireAssume is an evidence-producing developer tool, knowingly presenting fabricated experiment evidence, fake screenshots, hard-coded findings as discovered results, or benchmark numbers that were not executed is also inconsistent with project standards.
